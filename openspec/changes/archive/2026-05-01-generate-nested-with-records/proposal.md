## Why

Сейчас экстеншен-методы `With_` генерируются только для свойств объекта, на котором стоит атрибут `ExtendedWith`. Это ограничивает удобство использования для композиций и record-объектов: чтобы обновить вложенное record-свойство, приходится вручную создавать новый вложенный объект.

## What Changes

- Генератор будет строить **все пути обновления** (включая односегментные) через **единый конвейер**; “верхний” `With_<Property>` — частный случай пути длины 1.
- Для каждого пути (и для `TryWith_` / `With_..._OrThrow` при nullable record-сегментах) генерируется **полный набор из восьми перегрузок** (значение / `Task<>` / синхронный и асинхронный `Func` × `this Root` / `this Task<Root>`), симметрично существующему API одного уровня.
- Вложенные пути обновляют leaf (или целевой record-узел на префиксе) без ручного конструирования промежуточных объектов; `_OrThrow` использует **явный** `NullReferenceException` с информативным сообщением.
- Зафиксированы правила для нескольких уровней вложенности, nullability, доступности сеттеров/`init` и строгой обработки коллизий базового имени метода, возникающих из-за неоднозначного `PathSuffix`; добавлены тесты на генерацию и edge-cases.

## Capabilities

### New Capabilities

- `nested-with-for-record-properties`: Генерация вложенных методов `With_` для свойств, чей тип является `record`, включая рекурсивную вложенность и базовые правила исключений/ограничений.

## Impact

- **Код**: проект(ы) с source-generator’ом, отвечающим за `ExtendedWith` и генерацию `With_` методов.
- **Публичный API**: расширение набора генерируемых методов (аддитивно). Возможны ошибки генерации из-за коллизий базовых имён методов (неоднозначный `PathSuffix`) — потребуется строгое правило разрешения конфликтов в design/spec.
- **Производительность генерации**: потенциальный рост объёма сгенерированного кода и времени анализа, особенно при глубокой вложенности record-типов.
